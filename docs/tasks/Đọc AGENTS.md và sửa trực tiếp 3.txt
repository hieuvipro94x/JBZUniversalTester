1. PROBE PREVIEW QUARANTINE — SỬA ĐÚNG PRECEDENCE
======================================================================

Audit toàn bộ:

BoardIoDecoder
ProductionProbePreview
OnProductionProbePreview
_pendingProductionProbePreview
TakeProbePreviewForFrame
TryDetectInlineProbeContacts
OnBoardFrameReceived
TestEngine.ProcessFrame
ProbeContactClassifier
ProductEvidence
Wrong/Short classifier
Product start sound

Self-test hiện cố tình:

PublishProbePreview(
    ActiveIo=[1],
    Sequence=50,
    ScanGeneration=1)

sau đó:

Publish(
    FrameSeq(50, (230, new[]{1}))
    ScanGeneration=1)

Requirement:

preview và complete frame có cùng:
- Sequence
- ScanGeneration

thì complete frame probe-like tương ứng phải được QUARANTINE trước khi:

- TestEngine.ProcessFrame
- ProductEvidence
- ProductDetected
- WrongCandidate
- ShortCandidate
- product-start sound
- counter
- relay

Acceptance của case này:

previewEngine.FramesProcessed không tăng
CurrentProductionRuntimeState == WaitingForProduct
WrongCandidateCount == 0
_productStartSoundPlayed == 0

Không sửa test để bỏ requirement này.

NHƯNG không được khôi phục bug trước:

IO9 ↔ IO10
hoặc IO40 ↔ IO41
là exact physical connection thật
thì không được luôn luôn biến thành PROBE_ONLY.

Phải phân biệt rõ:

A. Probe-like signature:
- repeated target / fan-in
- early preview cùng sequence/generation
- không có authoritative exact physical pair

=> matching frame được quarantine khỏi product/fault engine.

B. Exact physical connection thật:
- direct/canonical edge evidence thật giữa 2 IO
- đặc biệt reciprocal/bidirectional evidence nếu protocol cung cấp
- không phải fan-in sweep của đầu dò

=> đi vào physical topology / Wrong / Short path phù hợp
=> không bị Probe preview nuốt.

Không được dùng rule quá rộng:

"có preview => bỏ mọi frame"

nếu làm direct physical pair mất.

Thiết kế một helper authoritative, ví dụ:

ShouldQuarantineProbeFrame(preview, frame)

dựa trên:
- generation match
- sequence match
- probe signature
- physical-edge evidence.

Pending preview phải one-shot:
- consume đúng frame
- không ảnh hưởng frame sau
- stale generation phải discard
- stale sequence phải discard
- không dùng TTL dài gây nuốt product frame sau.

Thêm/giữ regression tests:

1. Early preview + matching probe-like complete frame
   => quarantine.

2. Preview generation cũ + frame generation mới
   => không quarantine frame mới.

3. Preview sequence 50 + frame 51
   => không quarantine 51.

4. Direct physical IO9↔IO10
   => vẫn được phát hiện physical connection/short theo mode.

5. Probe thật
   => không trở thành Short/Wrong.

6. Probe release
   => Product presentation/state phục hồi đúng.

Regex.Matches(

$"Hardware.DeviceFault.{source}"

3. PASS ORDER — DB SAFETY + UI RESPONSIVENESS
======================================================================

Audit:

RunAutomaticPostContinuityAsync
RecordCompletedProductAsync
TriggerPassUi
PauseProductionScanForFinalPassAsync
PASS relay sequence
MARKING
JIG
label
counters/LOT

Requirement cuối cùng phải đồng thời thỏa 2 điều:

A. DATABASE SAFETY

Không được:

TriggerPassUi
MARKING
JIG
completed PASS counter

trước khi completed Product result đã persist/commit thành công.

Nếu DB commit FAIL:

- không PASS UI
- không MARKING
- không mở JIG như PASS
- relay safe OFF
- không tăng PASS/LOT từ uncommitted result
- báo persistence fault đúng domain.

B. UI RESPONSIVENESS

Sau khi DB commit thành công:

TriggerPassUi();

phải chạy TRƯỚC:

await PauseProductionScanForFinalPassAsync(ct);

Tức expected order:

continuity/resistance/waterproof success
↓
build immutable completed-result snapshot
↓
await RecordCompletedProductAsync(...)
↓
xác nhận DB commit success / exactly-once
↓
TriggerPassUi();
↓
await PauseProductionScanForFinalPassAsync(ct);
↓
relay MARKING/JIG sequence
↓
label/downstream behavior hiện hành

Không đổi thành:

Pause scan
→ chờ hardware
→ mới TriggerPassUi

vì làm UI PASS phản hồi chậm và self-test đã bảo vệ requirement này.

Relay vẫn tuyệt đối KHÔNG được chạy trước khi:

1. DB commit thành công
2. PauseProductionScanForFinalPassAsync hoàn tất theo safety requirement.

Sửa production code cho đúng thứ tự này.

Self-test hiện kiểm tra source ordering:

IndexOf("TriggerPassUi();")
<
IndexOf("await PauseProductionScanForFinalPassAsync(ct);")

Phải PASS bằng production implementation thật,
không thêm dead-code/string/comment giả để lừa source test.
