============================================================
4. PAGINATION PHẢI ĐỔI THEO ASC
============================================================

Đây là chỗ dễ lỗi nhất.

Nếu hiện tại keyset pagination đang dùng DESC kiểu:

HistoryAt < CursorHistoryAt
OR
(HistoryAt = CursorHistoryAt AND Id < CursorId)

thì phải đổi đồng bộ thành ASC:

HistoryAt > CursorHistoryAt
OR
(
    HistoryAt = CursorHistoryAt
    AND Id > CursorId
)

Trong đó:

HistoryAt =
COALESCE(t.TestStartedAt,t.StartedAt)

Không được chỉ đổi ORDER BY ASC mà quên đổi cursor,
vì sẽ gây:

- duplicate row
- mất row
- Load More nhảy sai
- page 2 quay lại dữ liệu cũ.

============================================================
5. STT PHẢI LÀ 1 → N
============================================================

Cột "Số thứ tự" KHÔNG được dùng trực tiếp:

- Tests.Id
- LOT
- database primary key
- serial lưu cũ

nếu chúng không phải ordinal của History view.

Tôi muốn:

STT = vị trí thực tế của row trong kết quả History đã filter + sort.

Ví dụ:

row đầu tiên  = 1
row thứ hai   = 2
row thứ ba    = 3
...
row cuối cùng = N

STT phải tăng:

1
2
3
4
5
...
N

KHÔNG:

1205
601
600
599
...

như hình hiện tại.

============================================================
6. STT PHẢI ĐÚNG QUA LOAD MORE
============================================================

Nếu page size = 200:

Page đầu:

1 ... 200

Load More:

201 ... 400

Load More:

401 ... 600

Không được page tiếp theo quay lại:

1 ... 200

Không được dựa trên Id DB.

Có thể triển khai STT ở ViewModel/presentation layer nếu đơn giản và an toàn:

displayIndex = loadedRowsBeforeCurrentPage + indexWithinCurrentPage + 1

NHƯNG chỉ nếu sorting/pagination đảm bảo append đúng thứ tự ASC.

Nếu query architecture phù hợp hơn với SQL:
có thể dùng ROW_NUMBER() OVER (...) trên filtered ordered set.

Chọn cách ÍT THAY ĐỔI và ít rủi ro nhất.

Không thay schema chỉ để thêm STT.

============================================================
7. STT SAU KHI FILTER
============================================================

Khi user filter:

- từ ngày
- đến ngày
- LOT
- File THT
- Kết quả
- Loại kiểm tra
- model/part nếu có

STT phải đánh lại từ:

1 ... N

trên chính filtered result.

Ví dụ toàn DB có 2,567 record.

Filter chỉ còn 95 record:

STT phải là:

1 ... 95

KHÔNG giữ ordinal từ toàn database như:

443 ... 537.

============================================================
8. SEARCH / RESET FILTER
============================================================

Khi nhấn TÌM KIẾM:

- clear current rows
- query lại từ oldest result của filter mới
- STT reset = 1

Khi nhấn XÓA LỌC:

- query full dataset
- oldest first
- STT reset = 1.

Không append filter mới vào dataset cũ.
