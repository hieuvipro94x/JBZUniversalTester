10. CHANGE BUDGET
============================================================

Đây là rule quan trọng nhất.

Sau audit, phân loại issue:

P0 = data loss / hardware safety / false PASS / false FAIL / crash
P1 = production logic / race / persistence / serious performance
P2 = cosmetic / maintainability / theoretical optimization.

CHỈ tự sửa:
P0
P1 có bằng chứng rõ.

KHÔNG sửa P2 trong release freeze.

Nếu gặp P1 nhưng fix lớn/rủi ro:
không sửa ngay.
Báo Remaining Risk.

Mục tiêu là GIẢM số dòng thay đổi.

Nếu audit không tìm bug production thật:
KHÔNG được tạo thay đổi giả để có commit mới.
