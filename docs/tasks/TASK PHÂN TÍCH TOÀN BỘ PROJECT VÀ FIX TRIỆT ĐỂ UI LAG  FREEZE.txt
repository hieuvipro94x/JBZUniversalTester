# 5. SCAN LOOP KHÔNG ĐƯỢC BUSY POLLING

Trace cũ có khoảng:

~2000 D2XX API call/s

trong khi board chỉ khoảng:

~14 complete frame/s.

Hãy kiểm tra implementation hiện tại.

Nếu đã dùng:

FT_SetEventNotification
FT_EVENT_RXCHAR
AutoResetEvent

thì đảm bảo thực sự wait event khi RX queue == 0.

Không được:

while(...)
{
FT_GetQueueStatus();
}

liên tục.

Mục tiêu:

* RX event đánh thức worker.
* Khi có data thì đọc toàn bộ available block hợp lý.
* Feed streaming decoder.
* Khi không có data thì worker sleep/wait event.
* Cancellation phải đánh thức worker ngay.

KHÔNG thêm delay lớn làm giảm phản ứng.

# 48. QUY TẮC CUỐI CÙNG

Ưu tiên theo thứ tự:

2. Không tạo D2XX lifecycle trùng.

5. Không spam Dispatcher bằng log/collection.
6. Không giảm tốc độ hardware.
7. Không thay đổi logic PASS/FAIL.
8. Không thay đổi protocol nếu chưa có bằng chứng trace.
9. Không thêm delay lớn để “giảm CPU”.
10. Build và kiểm tra toàn solution sau khi sửa.
