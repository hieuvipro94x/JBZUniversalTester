JBZUniversalTester - AUTO START / AUTO KEYSIGHT FLOW
===================================================

1. Board auto-connect
- MainViewModel starts Test.InitializeHardwareAsync() immediately when app starts.
- TestWindow reuses the same cached initialization task; it does not reconnect repeatedly.
- Connection buttons and Keysight resource textbox are removed from TestWindow status bar.

2. Keysight is demand-driven only
- TestEngine no longer creates resistance steps from appsettings when THT has none.
- Keysight is not connected at application startup.
- When all continuity networks pass:
  a) if model.ResistanceSteps is empty -> skip Keysight and complete PASS/relay.
  b) if model.ResistanceSteps has entries -> stop scan, auto-discover/connect Keysight through VISA,
     run resistance steps, show results, and only then allow final PASS/relay.
- Auto discovery uses configured Keysight.Resource first (if present), then USB?*INSTR.
- Candidate instrument must identify as KEYSIGHT / AGILENT / 34461.

3. THT resistance parsing
- ThtModelParser now retains all parsed model_text tables and looks for resistance tables/columns.
- Supported aliases include Korean/English variants for resistance, Min/Max, Channel, Name,
  Enable and RouteA/RouteB.
- No external/default resistance step is injected when THT does not contain one.
- IMPORTANT: exact resistance-table field names depend on the real THT authoring format. If an
  actual THT containing resistance uses different headers, provide that THT so aliases/routing can
  be mapped exactly from its real data rather than guessed.

4. Automatic UI flow
- Start test -> I/O tab.
- All I/O networks PASS -> Resistance tab automatically if resistance is required.
- Resistance FAIL -> no PASS relay.
- VISA/instrument error -> stop automatic sequence, do not increment product FAIL counter.
